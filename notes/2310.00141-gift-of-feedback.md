# The Gift of Feedback：论文阅读笔记 + 落地规划

- **论文**：The Gift of Feedback: Improving ASR Model Quality by Learning from User Corrections through Federated Learning
- **作者**：Lillian Zhou, Yuxin Ding, Mingqing Chen 等（Google）
- **出处**：arXiv 2310.00141v2，IEEE 2023（4 页，ICASSP 风格的工业论文）
- **一句话**：用联邦学习从用户对语音输入结果的手动修改中学习新词。先用词表过滤掉"不是纠错"的修改，再用检查点平均或混合训练防遗忘，最后用概率采样照顾长尾词。

---

## Part 1 论文阅读笔记

### 1.1 要解决的问题

语音识别模型在服务器上训练好后部署到手机，但语言一直在变。新出现的人名、热词在训练数据里没有，模型就会认错。用户看到错误后会手动修改，这些"音频 + 修改后文本"是天然的新鲜训练数据。联邦学习可以在数据不离开手机的前提下利用它们。

直接这样做会遇到四个问题：

| # | 问题 | 论文的解法 | 章节 |
|---|---|---|---|
| 1 | 用户修改大多是**改主意**，不是纠错，音频和文字对不上 | 词表过滤 | 2.2 / 4.2 |
| 2 | 手机内存算力有限 | 冻结 encoder，只训 decoder；MWER 用缓存候选 | 3.1 |
| 3 | 学了新词，**忘了旧能力**（灾难性遗忘） | 检查点平均；集中式 + 联邦混合训练 | 2.3 / 4.3 |
| 4 | 新词是长尾，且**彼此数量极不均衡** | 概率采样；客户端损失加权 | 2.4 / 4.4 |

### 1.2 方法

**(1) 联邦学习（2.1）**
每轮：手机下载最新模型 → 本地训练 → 只上传梯度 → 服务器聚合。一条训练样本包括：音频、模型原始转写、用户最终提交的文本。

**(2) 词表过滤（2.2）**
- 人工整理 241 个新词/热词（时事、科技、媒体、体育），比如 warnock、mbappe、sumeru。
- 只保留**有用户修改**并且**含词表词**的样本。逻辑是：模型不认识这些词，所以用户改的地方大概率是在纠正识别错误。
- 长期设想是用 Federated Analytics 统计"很多用户都在纠正的词"来自动生成词表（没有实际做）。
- 新词测试集：每个词写 4–5 个句子，用 **TTS 合成**音频。

**(3) 防遗忘（2.3）**
- **静态检查点平均**：θ_avg = α·θ_FL + (1−α)·θ_init，只用于评估和部署，联邦训练照常进行。
- **动态检查点平均**：每轮都做平均，下一轮从平均后的模型开始训练。
- **集中式 + 联邦混合**：服务器用原始训练数据同步训练，它的更新和手机上传的更新一起聚合，相当于"边学新词边复习"。
- α 的具体值论文没有给。

**(4) 长尾（2.4）**
- **概率采样**：每个词有采样概率 p ∈ (0,1]，越常见 p 越小；一台手机的参与概率取它所含词里最大的 p。每轮名额有限，降采样常见词的手机，就能把名额让给含稀有词的手机。
- **客户端损失加权**：L_client = Σ_u max_d(w_d)·loss_u，词越稀有 w 越大，一条语句取它所含词里最大的 w。
- p 和 w 的具体计算方式**论文没有给**。常见做法：p_w = min(1, C/n_w)，或者 p_w = (n_min/n_w)^α。

**(5) 模型（3.1）**
- 流式 Conformer Transducer（RNN-T）：encoder（声学）+ prediction network（类似语言模型）+ joint（融合，输出 wordpiece 概率）。生产环境用的是级联编码器的变体。
- **只训练 decoder**（joint + prediction network，150M 参数中的 40M），encoder 冻结、压缩，只负责提特征。依据是学新词主要靠上层，而且这样省内存。

**(6) MWER（3.1.1）**
- L_MWER = Σ_i P̂(y_i|x)·(W(y_i,y) − W̄)：按模型对 N-best 候选的概率，计算期望词错误数，再减去平均值。
- 直观理解：把"信心"从错得多的候选挪到错得少的候选上。和 RNN-T loss 一起用。
- 手机上跑 beam search 太占内存，所以缓存训练中产生的候选直接用（细节没有展开）。

**(7) 数据（3.2）**
- 预训练：多领域数据 MD（搜索、远场、电话、YouTube 等），其中包括 SF（短句）和 MF（中等长度句子）。
- 模拟实验：用 SF-LT（含长尾词的短句）微调；在 SF-LT 测试集上看新词，在 SF、MF 测试集上看遗忘。训练和测试的句子不重叠。
- 生产实验：用联邦学习 + 词表过滤后的真实用户数据；用 TTS 新词测试集看新词，用 MF 测试集看整体。

### 1.3 实验结果

**模拟实验（Table 2）**：学得多和忘得少很难兼得

| 训练哪部分 | 数据 | MF | SF | SF-LT（新词） |
|---|---|---|---|---|
| 基线 | — | 3.7 | 6.3 | 45.5 |
| 整个模型 | 只用新词 | 7.8 | 9.3 | **31.4**（−31%） |
| 整个模型 | 新词 + 旧数据 1:1 | 4.4 | 6.2 | 35.1（−23%） |
| 只训 joint | 只用新词 | 6.4 | 8.4 | 38.1 |
| 只训 joint | 新词 + 旧数据 1:1 | **3.8** | **6.3** | 40.6（−11%） |

**词表过滤的必要性（Fig 3）**：用全部有修改的样本训练，WER 迅速大幅恶化；用词表过滤后，WER 保持稳定。

**防遗忘（Table 3、4）**

| 设置 | Overall | Targeted |
|---|---|---|
| 基线 | 4.4 | 17.5 |
| Pure FL | 4.6（+4.5%） | 16.1（−8%） |
| **静态检查点平均** | **4.4** | **16.1** |
| 动态检查点平均 | 4.4 | 16.6 |

更新基线后（更强，3.5 / 16.6），FL-only 的整体 WER 变成 4.4（约 20% 的差距），检查点平均已经补不回来；**集中式 + 联邦混合**把整体拉回 3.5，新词保持 16.1。

**长尾（Fig 4、5，Table 5）**
- 训练中见过 ≥100 次的词，大多数错误全部修好（EC% = 100%）；见得少的词只修好了一部分。
- 概率采样让训练中见过的不同词从约 100 个增加到约 150 个（共 241 个）。

| 设置 | Overall | Targeted |
|---|---|---|
| Static Ckpt Avg | 4.4 | 16.1 |
| Client Loss Weighting | 4.4 | 16.0 |
| **Probabilistic Sampling** | 4.6 | **15.8** |
| Prob Samp + Static Ckpt Avg | 4.5 | 15.9 |

**推广到人名（Table 6）**：基线 5.7；用新词词表过滤 5.5；换成人名词表（美、中、印各前 1000 个婴儿名）5.4（−5%）；整体 WER 一直是 3.8。

**EC%（公式 3）**：EC% = (Acc_exp − Acc_base) / (1 − Acc_base)，即"原来错的里面，修好了百分之几"。

### 1.4 几个容易误读的地方

- **各张表的基线不同**（3.7/45.5、4.4/17.5、3.5/16.6、3.8/5.7）：模拟和生产用的模型、测试集都不同；生产模型中途更新过；人名实验又是另一个版本。**只能在同一张表内比较。**
- **MF/SF 这类整体指标本来就不指望下降**，目标是"不变差"。
- **句子级 WER 会稀释新词的收益**：每句只有 1 个目标词，基线的 17.5 里还有很多和新词无关的错误（包括 TTS 语音不自然造成的错）。更直接的指标是目标词本身的准确率，但论文只给了 Fig 4，没有汇总数字。
- **结论里没提损失加权**，和它只提升了 0.1 的结果一致。
- 产品没有点名。根据"输入法""用户修改输出文本""联系人名字"这些线索，**大概率是 Gboard 语音输入**（推断，论文未确认）。

### 1.5 批判性评价

**局限：**
1. 主结果提升中等（新词 WER 相对降约 10%）；长尾技巧的增量很小（0.1–0.3 个点），而且**没有方差和显著性检验**。
2. 词表是**人工挑选**的 241 个已知词；"自动发现新词 → 持续训练"的闭环没有演示，泛化性没有被证明（人名实验只是部分证据）。
3. 新词测试集用 **TTS 合成**，和真人发音差距大；训练用真人语音，测试用合成语音，分布不一致。
4. **没有和便宜方法对比**：服务器端 TTS 数据增强、上下文偏置（contextual biasing）。这是最大的缺口。
5. **没有验证过滤器的准确率**（被保留的样本里真正是纠错的比例）。
6. 很多细节缺失：p、w、α、训练轮数、MWER 权重；没有做"采样 + 加权"组合或 MWER 的消融实验。

**价值：**
1. 证明了"在生产环境联邦学习中用真实用户纠正数据训练"是**可行**的。
2. 一个有用的**负面结果**：不过滤直接用用户修改，模型会崩溃。
3. 联邦学习能拿到服务器上**不存在的真实发音数据**，这是 TTS 增强替代不了的，只是论文的评估方式没体现出来。
4. 整体 WER 不变、热门人名从错到对，对用户体验的影响远大于平均 WER 所能反映的。

## Part 2 落地规划：从用户修改中学习词库和 tone（类 Wispr Flow 产品）

### 2.1 背景和原则

- 产品形态：**用户口述 → ASR 原始转写 → LLM 整理润色 → 展示 → 用户可能修改 → 提交**。
- 不用联邦学习：在用户授权下，数据可以在服务器端处理。
- 目标：(1) 从用户修改中提取**个人和全局词库**；(2) 学习用户的**tone/风格**；(3) 建立配套的**评测集和指标体系**。

**从论文带过来的三条原则：**
1. **用户修改 ≠ 纠错。** 必须先分类，再当标签使用。
2. **新词是长尾且极不均衡。** 要设配额，并按频次分桶评测。
3. **学新东西一定会伤旧能力。** 必须有回归评测做守门。

**要补上论文缺失的四点：**
验证过滤准确率 / 用真人语音评测 / 和便宜方法对比 / 做统计检验。

### 2.2 数据采集：每条听写事件存什么

```
event_id, user_id(哈希), session_id, timestamp
app_context          # 在哪个 App 里（Slack/Gmail/IDE...），tone 强相关
audio_ref            # 音频（需授权）
asr_raw              # ASR 原始输出
asr_word_conf        # 词级置信度
asr_nbest            # 前 N 个候选（强信号，尽量保留）
formatted            # LLM 整理后的文本
final_text           # 用户最终文本
edit_log             # 编辑操作序列及其相对时间
commit_signal        # 判定为"最终"的依据：发送 / 失焦 / N 秒无操作
active_dictionary    # 当时生效的词库版本（用于归因和评测）
pipeline_version     # ASR / LLM / prompt 版本
```

- **raw、formatted、final 三份文本都要存**，否则无法判断是 ASR 的错还是 LLM 的错。
- **明确"最终文本"的观察窗口**，比如插入后 60 秒内，或者发送、失焦时。窗口之后的修改默认算内容重写。

### 2.3 处理链路

```
事件日志
  │
  ▼
① 规范化（大小写 / 标点 / 数字）→ 分离出纯格式修改
  │
  ▼
② 词级对齐：raw ↔ final、formatted ↔ final → 编辑片段（span）
  │
  ▼
③ 修改归因 + 分类 → A 识别纠错 / B 格式 / C tone / D 内容修改（丢弃）
  │
  ├─► A ─► ④ 候选词提取与打分 ─► 个人词库 / 全局词库 ─► ⑥ L0/L1/L2 使用
  ├─► B ─► 格式偏好画像
  └─► C ─► ⑤ tone 画像 + few-shot 样本库 + 偏好数据
```

**③ 归因**

| raw 里 | formatted 里 | final | 归因 |
|---|---|---|---|
| 错 | 错 | 用户改对 | **ASR 识别错** → 词库 |
| 对 | 被 LLM 改错 | 用户改回 | **LLM 润色错** → 修 prompt 或模型 |
| 对 | 对 | 换了说法或语气 | **tone** |
| — | — | 大段增删、改了意思 | **内容修改** → 丢弃 |

**③ 分类特征（先用规则，攒够标注再训练分类器）**

| 类别 | 判断特征 |
|---|---|
| A 识别纠错 | 替换前后**发音相近**（G2P 音素或拼音编辑距离，归一化后 < 0.3–0.4 作为起点）；原词 ASR 置信度低；新词在 **N-best 里出现过**；片段短；修改发生在转写后几秒内 |
| B 格式 | 规范化后完全相同 |
| C tone | 语义基本不变（embedding 相似度高 / NLI 双向蕴含），但用词变化大 |
| D 内容 | 语义改变、大段新增、修改发生得很晚 |

- 中文要特别处理**同音字**（权利/权力、在/再），需要结合 raw 和 formatted 归因。
- **必须做人工标注验证**：随机抽 500 条修改标注真实类别，A 类的 precision ≥ 90% 才能当训练标签或进全局词库。

**④ 候选词打分**

候选对，例如 ("I'm bappy" → "Mbappé")，特征：
- `n_events` 出现次数
- `n_users` **不同用户数**（最重要）
- `consistency` 同一个错误是否总被改成同一个词
- `oov_score` 在通用语言模型下概率低，说明是生词或专有名词
- `recency` 最近是否仍在出现
- `asr_conf_before` 原词的识别置信度

| 词库 | 入库条件（初始值，需要调） | 作用范围 |
|---|---|---|
| 个人词库 | 同一用户纠正同一词 ≥ 2 次；或 1 次且 N-best 命中、发音相似度高 | 只对该用户 |
| 全局词库 | ≥ k 个不同用户（k = 10–20）+ 一致性高 + 人工抽审 | 全体用户 |

- **衰减机制**：长期没有新证据就降权或移除，控制词库规模和误触发。

**⑤ tone**
- **统计特征画像**（按用户 × App）：大小写、标点、emoji、句长、填充词保留或删除、正式程度、称呼和结尾习惯。
- **检索式 few-shot**：存下 (formatted, final) 对；推理时按 App 和内容相似度检索 k 条放进 LLM prompt。不需要训练，见效快。
- **偏好数据**：攒够之后，以 final 为 chosen、formatted 为 rejected，做 DPO 之类的训练。
- **语义保真是硬约束**：不能让模型学成"帮用户改内容"。

**⑥ 词库使用：先便宜后昂贵，每一层都要证明比上一层好**

| 层级 | 方法 | 成本 | 适用 |
|---|---|---|---|
| L0 | LLM 后处理时带上用户词库和发音提示，把音近的错词纠正为词库词 | 很低，实时生效 | 个人词库，冷启动 |
| L1 | ASR 上下文偏置：Whisper 类模型用 prompt 放热词；或 shallow fusion / 热词 trie 加分 | 低 | 个人 + 全局 |
| L2 | 用确认过的纠错样本定期微调 ASR | 高 | 全局高频、L0/L1 解决不了的 |

**L2 直接套用论文的经验：**
- 冻结 encoder，只训上层（或用 LoRA）；
- 按 **1:1 混入通用数据**；
- 做**权重平均**，在回归集上扫 α 选最优；
- **每个词设样本上限** C（即 p = min(1, C/n)），防止热词主导训练；
- 在拿到稳定的主收益之前，不要急着上 MWER、损失加权这类复杂技巧。

### 2.4 风险清单

| 风险 | 对策 |
|---|---|
| 单个用户的怪癖进入全局词库（数据投毒） | 全局入库看**不同用户数**，加人工抽审 |
| 过度偏置：没说的词也被识别成词库词 | 误触发集 + 误触发率守门；词库衰减 |
| 锚定偏差：用户只改看到的错，final 不是完美标注 | 评测集的 final 必须人工复核 |
| C 类和 D 类混淆，模型学会改内容 | 语义保真检查；D 类宁可多丢 |
| 隐私 | 明确授权、PII 脱敏、保留期限；个人数据只在个人范围内使用 |

### 2.5 评测集设计

**(1) 结构：四个评测集 + 守门规则**

| 评测集 | 测什么 | 通过标准 |
|---|---|---|
| 目标集（含词库词） | 新词学会没有 | 显著提升 |
| 回归集（通用，覆盖各种场景） | 旧能力丢没丢 | 不显著变差（在置信区间内） |
| **误触发集**（音近普通词，不含词库词） | 偏置是否过头 | 误触发率 ≤ 阈值 |
| tone 集 | 风格是否像用户 | 回放距离下降 + 两两比较胜率 |

**(2) 数据来源（优先级从高到低）**
1. **用户纠错数据本身**（音频 + **人工复核**过的 final）。按用户、按时间切分：训练用 T 之前，测试用 T 之后。
2. **内部录音**：不同口音、语速、设备、环境（安静 / 嘈杂 / 远场）。
3. **TTS 合成**：只作补充，多音色、加噪声和混响，并且**单独报告**。

每个重点词 ≥ 10–20 句；或者按频次分桶汇总。论文每个词只有 4–5 句，太少了。

**(3) 指标**

| 指标 | 说明 |
|---|---|
| 整体 WER / CER | 回归守门（中文用 CER） |
| **目标词召回率** | 目标词被正确识别的比例，比句子 WER 直接 |
| **误触发率** | 没说词库词却输出了词库词 |
| B-WER / U-WER | 词库词位置 / 非词库词位置分别统计的错误率 |
| EC%（按词） | 原来的错误修好了多少 |
| **按频次分桶** | 0 / 1–10 / 10–100 / 100+，看长尾是否改善（复现 Fig 4） |
| **留出词** | 同类但不在词库里的新词，测方法本身能否泛化 |
| 大小写 / 格式敏感 WER | 专有名词大小写（iPhone）用户很在意 |

**(4) tone 评测**
- **回放评测**：拿留出时间段的真实听写记录，用新链路重新生成，计算**和用户最终文本的编辑距离**是否下降。
- **LLM 两两比较**：给出用户的历史风格样例，比较新旧输出哪个更像；评分标准固定，用人工标注校准。
- **语义保真**：NLI 或 LLM 检查没有改变原意。

**(5) 线上指标（把"用户修改"变成 KPI）**
- 编辑率（有修改的听写占比）
- 每 100 字符修改量
- **词库词再纠正率**（词库生效后，用户还需要改这个词的比例）
- 撤销率、重新听写率
- 上线走 A/B 测试

**(6) 工程规范（避免论文基线混乱的问题）**
- 评测集**版本化并冻结**，要改就发新版本；
- 同一张结果表只放同一个基线；每次实验都和固定基线一起重跑；
- **多个随机种子 + bootstrap 置信区间**；
- 定期刷新目标集，保留旧版本做纵向对比。

### 2.6 落地路线图

| 阶段 | 内容 | 产出 | 完成标准 |
|---|---|---|---|
| P0 日志 | 补全 raw / formatted / final / 置信度 / N-best / App / 编辑时间 / 版本 | 事件表 | 字段覆盖率 ≥ 99% |
| P1 标注 + 分类 | 标注 500 条修改（A/B/C/D）；规则分类器；调阈值 | 标注集 v1、分类器 v1 | A 类 precision ≥ 90% |
| P2 评测集 | 目标集 / 回归集 / 误触发集 / tone 回放集，优先真人语音 | 评测集 v1（冻结）+ 评测脚本 | 能对基线出带置信区间的报告 |
| P3 个人词库 + L0 | 个人词库入库、衰减；LLM 后处理纠正 | 个人词库服务 | 词库词再纠正率显著下降；误触发率不升 |
| P4 tone v1 | 风格画像 + 检索式 few-shot | tone 模块 | 回放编辑距离下降；语义保真通过 |
| P5 全局词库 + L1 | 跨用户聚合、人工抽审；ASR 上下文偏置 | 全局词库 + 偏置 | 目标词召回提升；回归集不显著变差 |
| P6 L2 微调（按需） | 冻结底层 + 1:1 通用数据 + 权重平均 + 每词配额 | 微调模型 | 相比 L1 在目标集上有显著增量，回归集守门通过 |

**关键原则：每往下一层，都要在评测集上证明比上一层更好，再继续投入。**
